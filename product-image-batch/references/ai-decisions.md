# AI 决策分工

本 skill 面向任意产品，没有固定品类脚本。清单字段、分析维度与示例用于帮助检查，不替 AI 下结论。每个需要判断的环节都应结合实际素材分析，保存可审阅的方案、依据和结论；不输出冗长内部思考过程，也不声称无法验证的事实已获证实。

## 各环节由 AI 主动完成的工作

| 环节 | AI 应完成的判断 |
| --- | --- |
| 素材理解 | 查看所有相关产品图，综合读取各份 TXT，识别商品、变体、实际可见特征、真实卖点、矛盾和信息缺口；主图候选规则只是线索，多图身份仍须判断 |
| 资料取舍 | 区分商品事实、供应商信息、营销说法与页面指令；为采用的事实保留来源，不把缺失变成杜撰 |
| 平台适配 | 根据站点、类目和实际官方依据判断主图及附图约束；缺规则时说明核验范围，不自行承诺合规 |
| 网站风格 | 实际观察参考页面，识别可借鉴的视觉语言及不适合当前产品/平台的部分，再形成统一方案；不机械复制网站或只看域名猜风格 |
| 图片规划 | 根据用户张数、资料与展示目标决定各图用途、内容分配和顺序，避免重复卖点、无意义凑数或虚构角度；图位名称不固定 |
| 场景设计 | 分析实际用途、人物/道具必要性、交互方式、尺度与物理关系、证据充分性和误导风险；先通过场景自检再花积分 |
| 构图与提示词 | 自行决定适合的布局、主体占比、留白、光线和具体约束，将产品依据与风格转成明确提示词；不把“高级、真实”等空话当方案 |
| 参考图组织 | 判断各图是商品主体、同款细节还是风格参考；排除不同产品混用，明确优先级，不让风格图改变产品身份 |
| 费用与执行 | 读取真实接口结果，核算张数与可核实费用，按状态决定查询、保存、继续或暂停；不靠余额变化猜任务扣费，不重复提交未知任务 |
| 视觉验收 | 将产物与原图、场景计划和平台要求对照，判断真实性、结构、用途、文字、物理关系及整套一致性；不能仅凭服务成功或“看着好看”通过 |
| 异常与替代 | 分析问题属于资料、连接、服务、生成还是保存；可自主处理的直接修，涉及新付费或事实缺失则遵循授权，不能静默重试花钱 |
| 整套交付 | 判断是否完整达到选定数量与用途，汇总未通过项和费用缺口，清楚区分文件保存、视觉合格和平台审核 |

## 用户只处理必要选择

已有信息不重复问。通常只需用户提供目录、选平台、张数、风格，以及确认费用范围。AI 可提出推荐供选择，但不把构图、道具安排、图位设计、提示词编写等日常工作甩给用户。

下列情况确需询问：产品型号或真实参数发生冲突、指定内容缺少不可替代的关键事实、需要新增费用/权限、用户偏好无法从上下文确定且显著影响结果。其他情况下，在既定数量、风格与预算内自行作出有依据的选择并连续执行。

不能获取所需页面/图片或无法理解产品时，应标明限制，选择资料足以支持的替代图位；用户明确指定且不能替代时保留待办。不为维持流程而伪造分析，不以一次付费生成试探缺失事实。

## 脚本与 MCP 的边界

脚本执行确定性工作：列文件、读取文本、校验路径/hash、保存状态、汇总实际记录、生成预览。MCP 负责按最终提示词生成。二者不能替代外层 AI 对产品与结果的判断。

生图前保存简短设计说明：产品依据、图位目的、构图/场景关系、采用风格、应保留与避免的内容；场景图同时记录 scene_plan 与 preflight。生成后保存具体检查结论与不确定项。分析记录是为了可核对，不能用填满字段冒充分析完成。自动化状态检查只能帮助发现遗漏，不能证明视觉判断正确。
