# 使用场景的规划与验收

“场景图”不是将产品和行业道具放在一起。先判断谁在什么环境、以什么方式使用商品，再决定画面是否有依据、是否能明确表达用途。生成前必须做以下分析，不能直接将说明里的关键词拼成画面。

## 生成前判断

为每个场景图位记录 scene_plan：

- purpose：这张图要表达的具体用途或可证实卖点。
- evidence：来自哪张原图、哪份说明的哪些信息；区分用户提供的事实与尚未验证的推断。
- interaction：使用者/产品/道具的空间关系，如何佩戴、握持、放置、安装或连接。
- feasibility：结构、尺寸、接触点、遮挡和实际使用方式是否可信；未知的兼容性不要当事实。
- composition：产品是否仍清楚可辨，画面如何避免误导。
- avoid：针对本场景的具体禁忌，不能只写“自然真实”。
- fallback：证据不足时采用什么安全的替代图位。

资料只有“适合某活动”“可搭配某装备”，不等于已经证明任意装备、任意安装位置都兼容。不根据行业联想自动增加道具。必要时查询可靠的产品使用资料确认常识性关系；查询结果不能用来证明当前型号的尺寸或兼容性。关键事实仍缺失且用户要求连续生成时，改用有依据的展示图，不为该图位打断整批、不胡编场景。

## 按具体产品判断，不限定品类

先识别产品身份、实际用途、使用者/使用对象，以及参考资料的覆盖范围，再决定合适的场景。以下是分析维度，按实际产品选择，不要求每个产品套用所有维度：

| 使用关系 | 需要判断的内容 |
| --- | --- |
| 穿戴、握持或人体接触 | 接触部位、姿态、尺寸关系、受力与遮挡是否合理 |
| 安装、连接或配套使用 | 接口、朝向、安装位置、空间与配套型号是否有依据 |
| 盛装、收纳或承载 | 开口、容量、物体尺度、支撑关系与用途是否可信 |
| 操作、加工或运动 | 操作方式、动作方向、活动空间与功能表现是否成立 |
| 家居摆放、环境融入 | 产品尺度、支撑面、空间用途与环境是否匹配 |
| 材料、部件或专业设备 | 有无应用依据，是否误画内部结构、加工过程或系统连接 |
| 其他或用途不明 | 先理解产品，不能归类就记录不确定项，不硬套场景 |

这些维度用于检查画面，不代表已验证具体产品的适配、性能或安全性。用户资料中的泛化用途描述，不证明特定型号、尺寸或任意道具的兼容性。不得为了增加戏剧性加入无关人物、设备或使用动作。

只有单张产品参考、没有足够使用关系资料时，优先独立展示、可见细节或有依据的中性环境展示。陈列图应明确为陈列，不能当作功能演示、安装效果或兼容验证。道具只在有必要且不误导时使用，不暗示随商品附送。

## 提示词与结果验收

### 调用前必须通过分析

在 scene_plan 中记录 preflight（pass / revise / insufficient_evidence）和 preflight_summary。只有 pass 才能提交付费生成；其余状态不允许以“先试一张看看”为由调用。

提交前逐项确认：用途有资料支持；关键交互位置可明确描述；没有未经证实的型号兼容或性能；道具必要且不会误导；提示词已落实正确空间关系和具体禁忌。检查发现问题先修订，不通过就改为有依据的替代图位；用户明确限定而无法替代时跳过并解释。不要以模型生成来替代前期产品理解。

对用户只展示简短的场景方案和依据结论，例如“当前资料不足以支持这张功能演示图，改为独立产品展示，不暗示未经验证的使用效果”，随后按既定数量与授权继续，不增加逐图确认。记录的是可审阅的方案和结论，无需输出冗长思考过程。不得将自检通过宣称为真实兼容测试或生成质量保证。

把已分析的 interaction 和 avoid 写进提示词，具体说明产品在哪里、与什么接触、哪些位置不能出现，以及不得新增的部件。风格不能覆盖物理关系和真实用途。

取得结果后先检查用途与交互，再看美观：

1. 是否真的呈现了规划的使用方式，而非商品与道具堆叠？
2. 接触点、位置、连接、活动部件或连接路径、遮挡、尺度是否合理？
3. 是否有悬浮、穿模、融合、多余部件或不可能的握持/佩戴？
4. 是否无依据地暗示兼容、承重、保护效果、食品接触或其他性能？
5. 商品外形、标识、颜色和配件是否保真？

不合理组合即使产品外形相似也不能通过。设 quality_status=failed、状态 needs_review，说明具体错误，不在交付中将其称为合格场景图。检查不了细节就标 unchecked/待确认，不声称物理关系已经核验。无额外重做授权时不新增付费任务，继续剩余图位并在最终预览突出标注；有授权时先修正规划，再重做，不能只追加“更真实”盲试。
