# 产品图批量生成：使用指南

本 skill 读取本地产品目录，用 Cocoon 生图 MCP 制作阿里国际站、亚马逊或自定义用途的产品图。它会引导你检查图片、选择平台和风格、查看余额、制作样图，再批量生成并保存结果。

它需要支持本地文件访问和远程 MCP 的 AI 客户端持续执行。只打开本文件或启动 MCP 服务不会自动生成图片；关闭聊天或中断任务后，需要回到聊天继续。它不会自动上传商品、发布店铺或充值。

## 1. 准备产品文件夹

建立一个根目录，每个产品放一个直属子文件夹，子文件夹以产品名称命名：

```text
D:\产品图片\
├─ 不锈钢保温杯\
│  ├─ 原图.jpg
│  └─ 产品说明.txt
├─ 折叠露营椅\
│  └─ 原图.png
└─ 桌面收纳盒\
   ├─ 原图.jpg
   └─ 细节.jpg
```

选择 `D:\产品图片` 这个根目录，不要选某一个产品目录。扫描只读取根目录下的一层产品子文件夹，不递归识别多层分类目录。生成结果、隐藏目录及链接目录会被排除。

建议使用清晰的 PNG、JPEG 或 WebP 原图，产品完整、无遮挡。同款多张图可以放在一起；不同型号、颜色或包装版本最好分开建产品文件夹，避免混用参考图。

| 文件情况 | 使用时如何处理 |
| --- | --- |
| 只有一张图片 | 默认作为产品原图 |
| 多张图片且只有一张名为“原图”或“original” | 优先作为主参考图，其余图检查后用作补充 |
| 多张图片且主图不明确 | 展示候选，让你选择 |
| 没有图片 | 提示补图或跳过该产品 |
| 图片损坏、打不开或不支持上传 | 指出文件，提示更换或另存为支持格式 |

注意：扫描器能发现 BMP/TIFF，但目前上传脚本不支持这两种格式；请先另存为 PNG/JPEG/WebP。文件后缀正确不代表图片内容一定可读，执行时还会查看原图。

### 可选：填写产品说明

每个产品可放一个 UTF-8 编码的 `产品说明.txt`，可从本目录 `assets/产品说明.txt` 复制模板：

```text
产品名称：不锈钢保温杯
真实材质：按实际商品填写
实际尺寸与单位：按已核实资料填写
包装内实际包含：杯子一个、包装盒一个
已确认卖点：按已核实资料填写
禁止修改的外形、颜色、标识或部件：保留杯盖、把手、商标及颜色
需要出现在图片上的精确文字（可留空）：
资料来源或需要注意的事项：
```

不填说明也可以做无文案展示图和适当场景图。没有真实资料时，不会自动编造尺寸、认证、性能、配件或不可见结构；依赖这些资料的图位会提示补充或跳过。

## 2. 让 AI 加载 skill

skill 的目录名是 `product-image-batch`。客户端已能识别该 skill 时，直接发送：

```text
使用 $product-image-batch，处理 D:\产品图片。
我要阿里国际站产品图，先做一款样图，风格确认后再批量生成。
```

如果客户端没有发现 `$product-image-batch`，先让它读取本目录的 `SKILL.md`，再按其中流程执行。例如在当前项目中可以说：

```text
请读取 D:\code\project-manage\project-manane-hub\skills\product-image-batch\SKILL.md，
按这个 skill 处理 D:\产品图片，先引导我选择平台和风格。
```

其他电脑需要替换为实际路径。仅将目录放进项目，不代表所有客户端都会自动安装或发现它；具体安装位置由客户端决定。

## 3. 连接 Cocoon 生图 MCP

第一次实际上传或生成前，AI 会检查连接。你可以先完成目录扫描和方案选择，不必一开始就配置 Key。

### 没有 Key 怎么办

访问 [Cocoon 官网](https://mcp.boomclaws.com/)，自行注册、登录，在管理页获取 API Key。账号注册、充值由你操作；不要把其他项目的 Key 当作生图服务 Key。

### 在客户端添加 MCP

在所用 AI 客户端的 MCP 设置中添加远程服务：

| 配置项 | 内容 |
| --- | --- |
| 服务名称 | `cocoon-ai`（可自定义） |
| 传输方式 | Streamable HTTP |
| 服务地址 | `https://mcp.boomclaws.com/mcp` |
| 请求头名称 | `Authorization` |
| 请求头值 | `Bearer 你的实际APIKey` |

`Bearer` 后有一个空格。把 Key 填在客户端的本机私密配置或密钥输入位置，不要发送到聊天、提交到 Git 或写进产品说明。

支持 JSON 配置的客户端可参考 `assets/mcp-config.example.json`，在本机私密配置中替换占位值；不同客户端界面和配置格式可能不同，不要直接覆盖整个现有配置。

配置后告诉 AI：“MCP 已配置，请验证连接。”AI 应发现实际提供的工具并查询余额。当前流程使用 `generate_image`、`get_image_task`、`get_points_balance`，字段以连接后实际工具 schema 为准。客户端未自动刷新连接时，可能需要按客户端要求重新连接或重启。

### 本地图上传还需要一个本机环境变量

本地图片不能直接作为 MCP 的公网参考图 URL。随 skill 提供的上传脚本使用同一个服务 Key，从环境变量 `COCOON_IMAGE_KEY` 读取凭据，上传后取得参考 URL。

在 Windows 中可打开“编辑账户的环境变量”，在用户变量中新增：

```text
变量名：COCOON_IMAGE_KEY
变量值：你的实际 Cocoon API Key
```

保存后重新启动执行脚本的 AI 客户端或终端，使它读到新变量。客户端中的 MCP 请求头不会自动变成脚本环境变量，两处配置用途不同，使用同一个 Key。已有可用 MCP 连接、仅缺上传配置时，只补环境变量即可。

不要让 AI 打印环境变量值来检查配置。它只需检查是否存在，并通过实际上传响应判断可用性。已知上传入口支持 PNG、JPEG、GIF、WebP、AVIF，脚本单文件上限为 20 MiB；默认目录扫描目前发现 PNG/JPEG/WebP/BMP/TIFF，GIF/AVIF 不会自动列入产品图片候选。要保持流程简单，优先准备 PNG/JPEG/WebP。

## 4. 跟随引导选择图片方案

AI 会分步询问，每次只处理当前需要的信息。你已明确提供的要求会直接复用。

### 平台与图片方案

| 选项 | 默认制作方式 |
| --- | --- |
| 阿里国际站套图 | 第一张白底，附图按产品选择场景、可见细节、真实卖点 |
| 亚马逊套图 | 主图按目标站点和类目规则制作白底，附图可用场景或细节 |
| 全部白底 | 主图和附图均白底，不凭空生成缺少参考的新角度 |
| 自定义 | 指定图片类型、数量及背景 |

亚马逊不等于所有图片都必须白底；“全部白底”是单独的制作选项。请提供亚马逊目标站点和商品类目，以便核对官方要求。阿里国际站首张白底是这个 skill 的默认制作约定，不代表所有类目都强制如此。

默认每个产品最多 1 张主图加 3 张附图。资料不足时会减少图位，不为了凑满数量生成虚构内容。可以同时选多个平台，但会分别建立图片任务并增加调用次数。

### 风格

可以选简洁商业摄影、工业科技、自然家居，也可以输入描述或提供参考图、网站截图。例如：

```text
附图用浅米色背景、自然窗光、简洁家居风格。
不要改产品颜色和商标，不添加图片文字。
```

风格参考控制背景、光线、配色和布局，不取代真实产品参考。仅有一张正面图时，不适合要求真实背面、内部拆解或隐藏接口图片。生图不能保证像素级保留，生成后仍要对比产品细节。

## 5. 查看余额、图片计划和样图

连接成功后会显示实际查询到的积分余额和查询时间。生成前会展示产品数、图片数、规格、样图范围，以及能核实的费用。

- 有当前可靠单价：展示预计积分；预计值不是扣费回执。
- 单价未知：只展示余额、数量和费用未知，不猜还能生成多少张。
- 余额不足：让你选择自行充值、减少图片或暂存任务；充值后重新查询。
- 查询失败：明确提示无法核实余额，不把它当作零余额，也不声称余额充足。

默认先做一个有代表性的产品样图。你可以回复：

```text
这个风格可以，继续处理剩余产品。
```

或者：

```text
主图保留，场景图背景太复杂，改成简洁家居风格，再给我看。
```

认可样图后，AI 刷新余额并继续剩余任务；合格样图直接计入正式交付，不重复生成。如果希望直接全量，可以一开始明确要求，但仍会展示计划和费用信息。

默认图生图规格为服务实际支持的 `1:1`、`1K`、不透明背景，模型以实际 schema 支持为准。需要其他比例、分辨率或透明背景可以提出。纯白背景与透明背景不同，不要混选。

## 6. 批量执行与结果检查

每张图片的执行顺序是：

```text
查看原图 → 上传/复用参考 URL → 提交生成 → 保存 taskId
→ 查询同一任务 → 获得结果 → 保存文件 → 对比原图检查
```

每张都引用真实原图，不会只用上一张生成图连续修改。检查包括外形、颜色、件数、商标、文字、配件、裁切和背景。图片生成成功不等于视觉检查通过，更不等于平台已审核通过。

正常情况下会定期报告已保存数量和需要确认的问题。单个产品缺资料或失败时可跳过并继续其他任务；认证失败、余额不足或整体服务故障会停止新提交。

结果不合格时，仅在你已经允许的重做范围内进行调整，每张最多额外一次；否则先提示你选择。提交超时、状态未知时不会自动重提，避免重复生成或扣费。

## 7. 图片保存在哪里

原图不覆盖。图片保存在每个产品的生成结果目录中，例如：

```text
D:\产品图片\
├─ 生成结果\
│  ├─ 批次-001.json        ← 任务记录
│  └─ 批次-001.html        ← 批次图片预览
└─ 不锈钢保温杯\
   ├─ 原图.jpg
   └─ 生成结果\alibaba\批次-001\
      ├─ 01-白底主图.png
      ├─ 02-使用场景.png
      └─ 03-产品细节.png
```

实际扩展名根据结果文件类型确定，不保证服务一定返回 PNG。重复制作使用新批次或版本文件，不覆盖已交付结果。

完成后，AI 应提供预览和输出目录的可点击路径，并报告成功、失败、跳过、待确认数量、最新余额及可核实扣分。HTML 预览应在允许读取本地图片的浏览器中打开；部分内嵌预览可能限制本地文件链接。

若结果 URL 已获得但本地保存失败，会明确标“待保存”，保留结果链接和任务 ID，不算本地交付完成。结果链接可能过期，应及时保存。服务记录、参考 URL、提示词和批次清单属于你的业务数据，不应随 skill 源码提交 Git。

## 8. 中断后继续、停止与局部重做

继续上次任务时，提供原批次清单路径：

```text
使用 $product-image-batch，继续 D:\产品图片\生成结果\批次-001.json，
先检查已有任务，只处理还没完成的部分，不重复提交未知状态的任务。
```

有 taskId 就继续查询原任务；已有结果就先保存；没有 ID 的未知提交需要核对服务任务历史后再决定。原图或参考图已变化时会提示新建批次。已经成功但文件丢失，会先尝试恢复已有结果，不默认再生一张。

局部重做可以这样说：

```text
只重做不锈钢保温杯的第二张，背景换成浅灰色。
产品外形、颜色和 Logo 不变，保留其他图片，先告诉我预计费用。
```

停止时说“停止本批任务”。AI 会停止新提交并保存进度；已经提交到服务端的任务可能仍继续执行，停止聊天不代表服务已取消或退款。

## 9. 常见问题

| 提示或现象 | 你可以怎么做 |
| --- | --- |
| 找不到 skill | 让 AI 读取本目录 SKILL.md，或按客户端要求安装该目录 |
| 扫描不到产品 | 检查是否选择根目录，产品是否放在直属子文件夹中 |
| 无法读取/保存目录 | 选择可访问、可写目录，或按客户端流程开放访问 |
| MCP 连接失败 | 检查服务地址以 /mcp 结尾、传输方式及 Bearer 请求头；按客户端要求重新连接 |
| 认证失败 | 在本机私密配置中检查/更新服务 Key，不把 Key 发到聊天 |
| MCP 能查余额，但不能上传本地图 | 检查执行脚本的进程是否读取到了 COCOON_IMAGE_KEY，设置后重启该进程 |
| 图片过大或格式不支持 | 准备不超过 20 MiB 的支持格式副本，保留原文件 |
| 一直等待生成 | 保留 taskId，稍后继续查询；不反复提交同一张图 |
| 提交超时，没有 taskId | 提交结果未知，可能已扣费；先在服务管理页查看任务历史 |
| 已生成但文件没保存 | 提供可写目录，使用原结果继续保存，不重新生图 |
| Logo、颜色或结构变了 | 指出具体差异，标记待确认，按授权范围局部重做 |
| 前后余额差额与本批费用不同 | 可能有充值、其他任务或未结算项，以实际任务扣费记录为准 |

遇到问题，AI 应说明受影响的产品、当前状态、下一步及是否可继续其他任务，不只给错误代码。余额、费用、服务能力和平台规则以实际查询为准。

## 10. 给维护者的辅助命令

普通使用由 AI 执行这些步骤，无需用户逐条敲命令。脚本要求 Python 3.12+；如果没有可用 Python，需先配置运行环境。命令中的 python 可替换为实际 Python 解释器绝对路径。

```powershell
# 以下在 skill 目录执行；也可使用脚本绝对路径
python -X utf8 scripts/batch.py scan "D:\产品图片"
python -X utf8 scripts/batch.py init "D:\产品图片\生成结果\计划.json" --manifest "D:\产品图片\生成结果\批次-001.json"
python -X utf8 scripts/batch.py pending "D:\产品图片\生成结果\批次-001.json"
python -X utf8 scripts/batch.py gallery "D:\产品图片\生成结果\批次-001.json"
python -X utf8 scripts/upload_reference.py --file "D:\产品图片\不锈钢保温杯\原图.jpg" --output "D:\产品图片\生成结果\参考记录.json"
```

计划格式见 `references/workflow.md`。辅助脚本负责扫描、初始化、查询待办、预览及参考图上传；生图调用、状态更新、结果保存与视觉检查由 AI 按 SKILL.md 编排执行。目前离线测试通过，尚未完成真实账户的完整端到端联调，首次使用必须验证实际工具 schema、上传、生成及保存能力。
