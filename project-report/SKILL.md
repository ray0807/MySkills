# 项目进度上报

读取当前项目代码、文档、Git 状态、当前会话及已有项目记录，补问缺失信息，上传完整项目快照，供用户的工作安排助手查询。

## 连接与 Key

项目连接保存在当前项目 `.project-hub/config.json`，属于本机私密配置，不上传、不提交 Git、不写入项目摘要。使用本 Skill 的 `scripts/hub.mjs` 管理和调用连接。相对路径从 Skill 目录解析；通过 `--project <项目绝对目录>` 明确目标。

- 当前项目没有配置时，先问“你要输入已有 API Key，还是生成新 Key？”。同时询问服务 HTTPS 地址（已有可靠配置时可沿用地址，但不从其他项目自动复制 Key）。已有 Key 可将新项目并入同一用户；新 Key 是全新用户。
- 用户选择生成后运行 `node <skill>/scripts/hub.mjs generate --project <目录> --url <服务地址>`。使用密码学随机 Key，不用模型编造。
- 用户选择输入已有 Key 时，可让用户在本机终端运行 `node <skill>/scripts/hub.mjs set --project <目录> --url <服务地址>`，交互输入，避免 Key 出现在命令参数或工具日志中。若用户已经在会话提供 Key，保存时避免再次输出。
- 已有配置时保留原 Key。仅在用户明确要求更换时使用 `--replace`，说明“换 Key 就换用户，旧项目仍属于旧 Key，不迁移；保留旧 Key 才能再次读取旧数据”。
- **每次生成、输入设置或更新 Key 后，必须提醒：“请立即复制并妥善保存这个 API Key；在其他项目或工作安排助手中使用同一个 Key，才能访问同一组项目。换 Key 就换用户，旧数据不会迁移。”** 自动生成脚本在本机显示 Key 和该提醒。告诉用户本机配置路径，用户可从该文件复制。最终回复再次提醒复制保存，但不要重复粘贴明文 Key。
- 未完成选择或配置时，不擅自生成、不上报。缺少服务地址时不要将 Key 发送到猜测的地址。生产仅接受 HTTPS；本地允许 localhost HTTP。

## 整理与反问

用稳定项目 ID，首次默认使用仓库名的字母数字、短横线形式，保存在本机配置中；避免每次产生新 ID。查询已有记录：`node <skill>/scripts/hub.mjs get --project <目录>`。查询失败时不得视为空项目并覆盖；报告故障，保留本地整理结果。明确不存在时再建新记录。

先从已有资料提取事实，不重复询问已有明确答案。对缺失或矛盾的信息分轮询问，每轮集中 2–3 个相关问题，优先目标、完成标准、当前阻塞。覆盖：

- 项目目标、使用者、背景、成功标准和验收条件；
- 当前阶段、必做功能、暂不做的范围、交付物；
- 已完成、正在做、待完成、待测试、已知缺陷与实际测试证据；
- 截止时间及其时区、里程碑、优先级、预计耗时；
- 任务依赖、阻塞、风险、需要用户做的决定及人工任务；
- 仓库、技术与运行环境、部署位置、协作者、下一步行动。

用户暂不确定或要求直接上报时，在 `metadata.openQuestions` 保留待确认问题，不无限追问。不猜测进度，不把未运行测试标成通过，不把计划当作完成。用户提供的耗时与进度估计标注来源。除非有明确依据，不强行填写估计数字或截止日期。

## 上传

参照 [references/report.md](references/report.md) 组装有效完整快照。以已有记录为基础更新，保留仍有效的任务、未解决的问题和扩展信息；字段缺省可能清空旧列表。不可包含 API Key、凭据、环境变量值或无关私密内容。

展示简短摘要与待确认项。用户调用本 Skill 已授权上报，不额外要求重复确认；有必要补问的答案仍应等用户回答。将快照存到 `.project-hub/report.json`，执行 `node <skill>/scripts/hub.mjs report --project <目录>`，通过 `/mcp/report` 的 `report_project` 上传。已有连接工具可直接使用，但须核实服务地址和身份一致。脚本通过 `/mcp/query` 的 `get_project` 获取旧数据，不依赖预先安装 MCP SDK。

只有收到成功响应才报告上传成功。失败时保留快照，说明可重试，不宣称完成，不自动更换 Key。最后给出项目 ID、已上传内容摘要、需要用户处理的事项；发生 Key 设置或更换时再次提醒复制保存。
