# 验收范围：先能做生意，再能获取与保留流量

标记：G=正常交易上线的门槛；R=重要质量项；O=优化；C=满足条件时检查。状态与严重性分开：未知不是失败，缺支付证据也不是通过。G 项未验证必须进入结论缺口。下列严重性按实际影响调整，不机械把所有缺项变成宕机。

## 1. 正式环境与访问

| ID | 级别 | 检查与验收方法 |
| --- | --- | --- |
| ENV-01 | G | 正式域名/DNS/HTTPS/TLS 可用；关键页不反复 5xx，不跳错域名。检查证书主机名、信任链、有效期。 |
| ENV-02 | G | 正式店解除意外密码墙/维护模式；测试站仍有合适隔离。不把开放测试站当 SEO 成功。 |
| ENV-03 | R | HTTP 与 www/非 www 归一到指定正式版本，无循环/多余跳转；静态资源和支付路径无混合内容。 |
| ENV-04 | R | 导航、Logo、Banner、页脚、分类与搜索结果链接有效；真实 404 有返回购物入口，不把所有 404 重定向首页。 |

## 2. 商品真实性与可购买性

| ID | 级别 | 检查与验收方法 |
| --- | --- | --- |
| CAT-01 | G | 样本可售商品有正确售价/币种/规格与购买入口；图片对应实际商品，非占位图或错误变体。 |
| CAT-02 | G | 切换尺码/颜色/组合，SKU、价格、图片、库存与购物车一致；缺货不能当有货卖，预售须说明。 |
| CAT-03 | R | 描述说明材质/尺寸单位/用途/包装数量与必要限制；无未替换模板、虚构评分、无依据认证和夸大效果。 |
| CAT-04 | C | 划线价、优惠、套餐、订阅/试用和倒计时有真实条件及有效期；优惠不适用时解释清楚。 |
| CAT-05 | C | 数字商品交付方式、下载权限；订阅频率、续费、取消；定制商品选项与交期按业务逐项验证。 |

## 3. 导航与购物车

| ID | 级别 | 检查与验收方法 |
| --- | --- | --- |
| CART-01 | G | 商品选择→加购→购物车，正确 SKU/数量/单价；加减/删除不异常，刷新状态合理。 |
| CART-02 | G | 总额计算与币种正确；不能悄悄添加未选择的收费商品/服务。 |
| CART-03 | R | 搜索相关结果与零结果、分类/筛选/排序有合理反馈，关键商品不只藏在搜索里。 |
| CART-04 | C | 访客结算、账户登录/退出、忘记密码；不要求与购买无关的字段。社交登录可用时验证。 |

## 4. 结算、支付、失败恢复

| ID | 级别 | 检查与验收方法 |
| --- | --- | --- |
| PAY-01 | G | 核心目标市场可进入结算，支持地址可选择有效配送与至少一种已配置支付方式。展示图标不等于支付可用。 |
| PAY-02 | G | 商品小计、折扣、运费、税/费用、货币与最终金额一致，并在提交前可见。 |
| PAY-03 | G | 获授权测试支付成功后，支付状态与订单状态一致；不能只看感谢页。生产上线前支付已退出测试模式需后台证据。 |
| PAY-04 | G | 测试失败/取消/超时/需要额外认证的支付路径有正确状态，不标成功、不重复扣款或生成重复已支付订单。 |
| PAY-05 | G | 支付通知/Webhook 或相应平台机制正确处理，重复通知只履约一次；离开返回页后付款也不丢单。 |
| PAY-06 | C | 跨域托管支付、钱包、延迟支付与订阅按实际启用方式验证；不要求所有站点支持全部支付方式。 |

## 5. 配送、税费与履约

| ID | 级别 | 检查与验收方法 |
| --- | --- | --- |
| FUL-01 | G | 目标市场覆盖可售商品，配送限制、处理时间与预计运输时间清楚；排除市场不会假装能发货。 |
| FUL-02 | G | 运费规则与商品重量/地区/订单门槛相符；免费运费边界、偏远/大件附加费在样本结算核实。 |
| FUL-03 | G | 测试订单进入正确后台/仓库流程，库存变化符合平台规则；实际收单通知到商家。 |
| FUL-04 | R | 买家确认邮件、商家提醒、发货/追踪、取消/退款状态在获授权测试中可追踪；收件/垃圾箱结果需实际证据。 |
| FUL-05 | C | 税、关税、进口责任、发票按目标地区/产品与经营主体确定；核对配置及公开说明，不凭前台计算认证税务合法性。 |

## 6. 信任、政策与联系

| ID | 级别 | 检查与验收方法 |
| --- | --- | --- |
| TRUST-01 | G | 实际商家身份与有效联系途径明确，不是模板邮箱/空联系电话；有可用售后入口。 |
| TRUST-02 | G | 退换货/退款/配送政策可从购买前找到，内容非空，说明时间、条件、流程与费用；不要求所有商品一律可退。 |
| TRUST-03 | R | 关于我们、FAQ、营业/回复时间与品牌一致；支付标志、客户证言、资质有依据。 |
| TRUST-04 | C | 隐私、条款、Cookie 与销售市场相关法定披露由适用规则核验；有链接不等于法律合规。政策与实际数据处理/退货行为一致。 |

## 7. 移动、浏览器与可访问性

| ID | 级别 | 检查与验收方法 |
| --- | --- | --- |
| UX-01 | G | 移动商品变体、加购和付款按钮可见可点；浮层/Cookie/聊天组件不挡关键操作，键盘弹起后可提交。 |
| UX-02 | R | 窄屏不溢出关键内容，图片可读，无空白/加载死循环；桌面与移动导航/表单正确。 |
| UX-03 | R | 键盘可到关键控件，焦点可见，字段有标签与明确错误提示；图片替代文本、色彩/对比基本检查。不能凭自动分数宣称 WCAG 合规。 |
| UX-04 | C | 核心流量浏览器/设备的真实测试（如 Safari 钱包）；浏览器模拟只说明对应仿真条件。 |

## 8. SEO 索引与内容

| ID | 级别 | 检查与验收方法 |
| --- | --- | --- |
| SEO-01 | C | 依赖自然搜索的正式站，核心页不被意外 noindex/X-Robots-Tag/登录/robots 禁止；测试环境限制在上线切换时复核。 |
| SEO-02 | R | 标题/描述匹配页面、关键内容可渲染、H1 有合理语义结构；重复标题抽样定位。keywords 缺失不是 Google SEO 问题。 |
| SEO-03 | R | canonical、重定向、站内链接与 sitemap 对规范版本一致，不指向测试域/错误商品/全站首页。缺 canonical 本身不等于阻断。 |
| SEO-04 | R | sitemap 可解析，提交的核心 URLs 返回正确内容，不混入 noindex/搜索/购物车/测试页面；robots sitemap 宣告位置正确。小站没有 sitemap 不是绝对无法索引。 |
| SEO-05 | R | 首页→分类→商品有可抓取链接；分页/无限滚动及过滤 URL 按实际实现处理，不靠搜索框才能找到所有商品。 |
| SEO-06 | C | Product/Offer/变体/Breadcrumb/商家政策等结构化数据匹配页面；按对应 Rich Results Test 验证，不将 JSON 语法通过当富媒体资格通过，不伪造评论。 |
| SEO-07 | C | 多语言有稳定 URL、语言代码、hreflang 互相引用与正确 canonical；货币切换与语言切换区别核验，不默认要求每个单语站有 hreflang。 |
| SEO-08 | R | Search Console 所有权/提交/索引查看需账户证据；新站未收录不直接判故障，记录发布与观察时间。 |
| SEO-09 | O | OG 分享标题/图/URL、内容质量与相关内部链接；社交图能访问及裁切正常。 |

## 9. 性能与稳定性

| ID | 级别 | 检查与验收方法 |
| --- | --- | --- |
| PERF-01 | R | 首页/分类/商品/购物车的移动实验室数据及实际交互；记录设备、网络、地域、冷/热缓存与工具版本。 |
| PERF-02 | C | 有真实流量时查看 LCP/INP/CLS 的字段数据与时间窗；无数据写 unknown，不造数。 |
| PERF-03 | R | 慢图、字体、第三方脚本和布局跳动按实测定位；不是一看到 JPEG 就断言必须 WebP。 |

## 10. 埋点、广告与市场适用项

| ID | 级别 | 检查与验收方法 |
| --- | --- | --- |
| DATA-01 | C | 已选 GA4/广告渠道：view_item、add_to_cart、begin_checkout、purchase/询盘事件在对应调试工具实收。 |
| DATA-02 | C | 金额/币种/商品 ID/transaction_id 正确，页面刷新不重复记购买；个人信息不直接写 URL/分析事件。 |
| DATA-03 | C | 目标市场需要的同意状态，首次/拒绝/同意/撤回均检查；弹窗出现不等于同意行为正确。Google 高级同意模式无 Cookie ping 不能机械判成违反同意。 |
| CHANNEL-01 | C | 需要 Shopping 时才核验 Merchant Center、商品 feed、售价/币种/库存/运费/退货信息一致及诊断；不是每家商城上线都必须开 Merchant Center。 |

## 11. 被动安全与运营

| ID | 级别 | 检查与验收方法 |
| --- | --- | --- |
| OPS-01 | G | 密钥/订单/个人数据没有明显公开暴露；只核验正常公开页面，不猜后台路径或探测越权。发现泄露仅记录脱敏证据。 |
| OPS-02 | R | 适合站点的安全头、第三方插件与登录配置；缺 CSP 等不自动等于漏洞，应用场景与平台能力决定。 |
| OPS-03 | G | 商家知道如何收单、履约与联系支付/平台支持，有异常责任人；自建站需可用恢复方案，托管站核验其实际恢复范围。 |
| OPS-04 | R | 域名/证书续期、监控告警、商品/订单备份与恢复证据、上线回滚与发布时间安排。无备份演练不写已验证。 |

## 12. 询盘型站点替代链路

不适用在线支付时说明站点目标，PAY/CART 项可 not_applicable，但用以下 G 项替代，不能把整条转化链删掉：LEAD-01 联系入口可用；LEAD-02 字段/上传/错误/重复提交有正确反馈；LEAD-03 授权测试询盘到达预期邮箱/CRM 且可回访；LEAD-04 询盘说明、隐私与报价流程清楚。发送测试询盘需指定测试收件人并获授权。
