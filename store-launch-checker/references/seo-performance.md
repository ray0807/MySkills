# SEO 与性能：配置、测量和上线时间不同

## 搜索前置条件

Google 自然搜索需能访问实际内容。上线前的密码或 noindex 可能是正确保护；检查计划要有正式站放行后复核。robots.txt 管抓取，不是身份认证，也不能单独保证不被索引。核心 SEO 页面应与商家索引意图对应，购物车/内部搜索/账户不要求索引。

首页、分类、商品、政策/内容等模板抽样：实际 title/描述与正文；JS 渲染是否有关键内容；规范 URL 与重定向/内链/sitemap 一致；商品链接可从分类到达。canonical 缺失只作建议/风险，错误指向更严重；多个冲突标签需复核。不要硬设每个 title 超 60 字必失败，也不要要求每页只能有一个 H1 才能上线。

meta keywords 对 Google 排名不起作用，不列成待修复事项。description 影响摘要展示，不保证 Google 原样采用。OG 是分享预览，不替代 SEO。Product/Offer 数据核对实际 SKU、价格、币种、库存；JSON-LD 能解析不表示 Google 富媒体验证通过。Rich Results 资格不保证实际展示。

多语言使用真实的对应页面与可验证 hreflang 引用；不将不同语言全指到单一英文 canonical。单语站无需 hreflang。Merchant Center 与 feed 是目标渠道条件项，不是普通商城所有场景的强制开户要求。新站刚发布没有收录并不自动失败，Search Console 用于验证和后续观察。

## 性能

当前 Core Web Vitals 是 LCP、INP、CLS，不继续用 FID 作为当前核心指标。良好参考阈值：LCP ≤2.5 秒，INP ≤200ms，CLS ≤0.1；真实用户评价按第 75 百分位，并区分移动/桌面。以当次官方资料为准。

Lighthouse 是控制条件下的诊断；它的 TBT 不能直接改名 INP。记录工具/浏览器版本、页面、设备/网络、运行时间及地域。一次结果波动可在同条件下复测，不能反复测到高分再只报最高值。

PSI/CrUX 可能有 URL 级或 origin 级、过去 28 天的数据；必须标注粒度。新站数据不足用 unknown，不阻止交付实验室诊断，也不编造“实际用户全部通过”。实验室分数与字段评价可以不一致。正式上线若业务确需字段证据则安排上线后复查，不把新站客观无历史当技术故障。

HTTP 完成耗时不是首屏、LCP 或网络 TTFB；脚本只标 http_elapsed_ms。图片压缩格式、大小/加载方式、缓存、字体、第三方脚本、JS 主线程工作按工具真实诊断提出修改，不能只靠“页面慢”推定 WebP 缺失或某插件为根因。

若 PSI API/工具需要 Key，先提示用户配置已有/缺失凭据；无此能力可用本地 Lighthouse。私有预发布 URL 不默认发送给第三方服务。自动无障碍审计仅覆盖部分问题，键盘/焦点/读屏等补充测试另记。
