# 证据与优先级

需求证据 `need_level`：
- `explicit`：原文明确采购目标产品，保留原文摘录和 URL。数量未知不影响明确求购的判定。
- `possible`：询价含义不清或来源只能看到摘要，进入待核验区。
- `signal`：新闻、公司经营范围或中标历史，单列，不作为采购线索导入主库。

有效状态 `validity`：`open` / `closed` / `expired` / `unknown`。open 需要页面明确开放或未截止的有效采购公告支持；有截止日期时比较用户时区和公告时区，冲突则核验。系统导入不自动推定状态。

确认状态 `confirmation`：`public-unconfirmed` / `buyer-confirmed`。后者需要获授权联系后，买家的明确回复、回复日期与可定位的记录引用；无法公开的邮件或会话可以用本地记录引用，不对外披露。仅找到联系方式不算确认。

身份 `identity_confidence`：
- `high`：需求发布者与公司有明确关系，且官方来源进一步支持公司身份或联系方式归属。
- `medium`：公司、地点、业务和职位等多个独立要素相符，但缺少发布者与公司之间的直接关系；跟进先确认身份。
- `low`：只有同名、国家或附件元数据，不作为可直接报价对象。
- `unknown`：无法建立关系。

每个联系人单独保存来源与 confidence。公司总机/公共邮箱、采购专员和平台入口区分记录；LinkedIn 链接不一定无需登录可联系。附件作者不是采购联系人证明，附件正文出现的公司/采购编号优先。

供货匹配 `fit`：`matched` / `partial` / `mismatch` / `unknown`。核对产品、认证、起订量、交期、供应商来源限制；未知认证不假定具备。限制不匹配应写明原因。

优先级（统一使用此处规则）：
- `A`：明确需求、仍开放、身份 high、存在经验证的业务联系路径或已获授权可用的平台入口、供货 matched。
- `B`：明确需求，但有效性、身份、联系权限或部分供货条件仍需确认；逐项列出缺口。
- `C`：可能需求、弱身份或需要合作商才能执行。闭标、过期和供货 mismatch 只保留历史，不列入当前跟进清单。

数量与采购金额是商业排序因素，不是真实性证明。平台 VERIFIED、信任分或付费会员标识也不等于需求有效。发现身份矛盾、付款异常或伪造证据时标注具体事实并暂停推荐，不按姓名或国家直接判断真假。
