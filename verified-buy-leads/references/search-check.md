# 搜索渠道预检：验证实际返回，不只看工具成功

启动正式查询前小样本预检，仅使用宿主真实已有工具。不要求用户开接口、提供 Key、登录账号或付费。截图里某引擎可用不代表当前环境或未来一定可用，不固定首选厂商。

## 检查步骤

1. 盘点可调用的搜索工具及已有网页/浏览器能力，分别记录 engine（搜索引擎）和 access_mode（内置搜索工具 / HTTP抓取 / browser-serp）。同为 Google，抓取失败不等于浏览器搜索不可用。如果当前环境已有浏览器 Google 等搜索结果页有效、内置搜索漏结果的实测，就优先沿用已验证 browser-serp 路线；否则小样本对照再选。不要固定“内置工具成功就不试其他来源”。
2. 对 Facebook、Instagram、YouTube 分别做一个宽松对照查询，例如 site:facebook.com 产品词，不加多个引号、国家和采购限定。无结果时用另一个已知相关的宽泛术语复测，避免把产品冷门误判成工具坏了。
3. 记录搜索**实际返回的外部结果 URL**，不拿标题、摘要里出现 facebook.com 当域名命中，不把广告/搜索导航混入分母。同域子域算命中，facebook.com.example.org 不算。搜索跳转链接用工具返回的真实目标地址；无法解析的重定向标未解析，不伪装成目标链接。
4. 每个样本尽量取至少 5 个不同结果。5 个以上且目标域占比至少 80% 标 usable-sample；混入明显异域结果标 site-filter-unreliable，表示此样本定向过滤不可靠，不武断断言工具一定吞了 site:。少于 5 个是 inconclusive-small-sample；空结果是 inconclusive-empty，不是平台没客户。重复同一 URL 不扩充样本。
5. 对异常查询去掉复杂操作符再复测一次；仍异常就切换已有的替代搜索来源。内置搜索零结果或抓取为空壳时，若环境已有可操作浏览器，先在浏览器内打开 Google 等搜索结果页，对同一查询实测；不要继续同一种 HTTP 抓取反复重试。DuckDuckGo/Bing 等也须实际验证，不固定某引擎有效。不假设存在 browser.search、HTTP 或特定引擎接口；没有替代工具就保留范围限制，不要求用户配接口。
6. 返回阻断页、人机验证、错误时分别记 blocked/captcha/error，不能因为 HTTP 200 就记成功，也不能靠零 URL 自动猜验证码。验证码/登录墙不绕过，切换可用来源；所有路线失败则如实交付已有名单与未覆盖范围。

一次 usable-sample 只表明链接发现可用，不证明能读社媒内部、评论或私密群，不证明产品相关性和买家意图正确。进入正式查询后仍抽查实际域名、产品相关性及买方口吻；某平台通过不等于其他平台通过。结果明显跑偏时重新预检，缓存按 provider+target_domain+query语法区分，不永久记引擎有效或无效。

## browser-serp：只读搜索结果页，不进入社媒原帖

打开搜索引擎结果页属于链接发现流程，**不违反 open_source_pages=false**；该配置限制目标社媒原帖读取，不限制搜索结果页。使用宿主当前真实可操作的浏览器工具，提交查询、等待结果渲染、读结果卡片标题/摘要/实际目标 URL 及可见时间。浏览器加载 JavaScript 后出现结果，与 HTTP 只拿到空 HTML 壳是不同能力；不能把其中一条失败写成整个平台 blocked。

- 一旦当前浏览器路线在定向查询上表现更好，记录 engine/access_mode、日期、目标域与样本，正式搜索优先用它；不把用户此次 Cursor 经验写成 Google 永远有效或全部环境自带浏览器。
- Facebook、Instagram、YouTube 分别按词族/场景/当地语言查询；精确短语只是其中一组，宽松查询和替换/痛点词也要跑。仅保存结果页内容即可，不点击原帖、不要求社媒账号。
- 沿可见下一页按钮或工具实际分页能力继续读，记录 query、page_number/游标、已读末项及停止原因。不能凭空拼页码并当作已读取。没有下一页、范围耗尽、预算到达、重复结果趋于饱和或验证码都记真实原因；未完成队列保留，下轮继续。
- 有验证码时保留已收录链接及当前页，暂停该搜索路线；有其他已验证免费路线就继续，否则说明需要用户在浏览器手动处理后才能恢复。不自动解验证码、不要求等到改天、不无限重试。
- 已授权的只读客户查找中，切换已有搜索工具或浏览器搜索结果页属于同一任务。发现更好路线后直接重跑受影响查询、追加去重到同一客户名单.csv，不以“要不要现在重跑”结束。新增付费、登录或其他权限时才另作处理。
- 搜索摘要里的“11个月前/2年前”原样保存为搜索显示时间，不当原帖核验日期。旧但相关的买家求助可标历史/时效待核验；当前时间窗口优先新结果，不把两年前帖子写成正在采购。只有历史摘要日期，不自动推断需求已关闭。

## 离线辅助检查

agent 收集实测结果到数组后可运行：

`python scripts/search_probe.py --input <探测JSON> --output <数据目录>/search-capabilities.json`

示例（占位链接，不能当实测结果）：

```json
[{"provider":"实际工具/来源名", "query":"site:facebook.com 产品词", "target_domain":"facebook.com", "checked_at":"2026-10-15T12:00:00+08:00", "response_state":"ok", "result_urls":["https://www.facebook.com/example"]}]
```

脚本只核对已有结果、统计域名命中并标记样本状态，不联网、不代替 agent 搜索，不自动识别人机验证。response_state 必须根据实际响应填写。索引链接保存逻辑和用户输出不变：只交付客户名单.csv，不额外交付预检报告或要求用户理解工具配置。

search-capabilities.json 是内部运行记录，含 provider、query、target_domain、checked_at、result_urls、response_state、status、sample_size、target_count、target_ratio、invalid_count；另由 agent 记录 engine、access_mode、切换原因、备选来源、浏览器页码/续查位置及后续正式查询表现。全路线无结果要区分引擎失败、样本不足和真实查询零命中。
