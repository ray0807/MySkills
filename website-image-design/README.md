# website-image-design 使用说明

这个 skill 给 Codex 正常的网站开发增加 **Cocoon 生图 MCP** 能力：需要图片时生成，保存到项目里，接入页面并检查效果。网站分析、设计、文案修改、代码实现和测试继续按正常开发方式处理。

**不要求填写固定表单，不强制先做样图，不增加一套设计审批流程。** 已明确的需求直接执行，只有关键歧义、缺素材或费用授权不明确时才询问。

## 1. 使用前准备

- 在 AI 客户端打开实际网站源码项目作为工作目录，确保能访问代码和图片资源。
- 客户端能加载这个 skill，并支持远程 MCP 调用。需要上传本地图时，还需能够运行 Python 脚本。
- 提供你要改的页面或区域，可以是一句话、页面地址、截图框选或组件名称。
- 涉及真实商品时，准备真实产品图；有产品资料、品牌规范可以一并提供。

不需要提前写生图提示词或决定每张图的构图，这些由 AI 分析处理。没有配图需求时，不必配置 MCP 或 Key。

### 让客户端识别 skill

名称是 `website-image-design`。客户端已经识别时，用 `$website-image-design` 调用。

如果没有识别，让 AI 读取本目录的 `SKILL.md` 并按其执行。以当前仓库为例：

```text
请读取 D:\code\project-manage\project-manane-hub\skills\website-image-design\SKILL.md，
修改当前网站首页，需要配图时使用其中的 Cocoon MCP。
```

其他电脑替换为实际路径。把目录放进项目不等于所有客户端都会自动安装；也可以按所用客户端的 skill 安装方式安装完整目录。

## 2. 最简单的用法

打开网站源码项目，发送：

```text
使用 $website-image-design，帮我优化首页 Banner。
保持现有品牌配色，标题和按钮文案也一起调整，适配手机端。
需要图片时，用 Cocoon MCP 生成并接入源码。
先说明需要几张及可核实费用，在我授权范围内连续完成。
```

AI 会根据实际项目决定：哪些代码要改、现有资源是否能用、是否需要新图、生成什么内容、如何构图以及如何接入。

如果已经有明确数量和授权，可以直接说：

```text
修改首页 Banner，用 Cocoon 生成1张新的背景图。
参考我提供的产品原图，采用自然家居氛围，文案保留在页面代码里。
本次允许生成1次，不自动额外重做。完成图片替换和移动端调整。
```

没有清楚的风格也没关系，可以描述业务目标，例如“更简洁”“突出产品”“减少杂乱”。AI 会结合现有页面提出合适做法，重要歧义才会追问，不要求你先写设计方案。

## 3. 怎么告诉 AI 改哪里、参考什么

### 用截图框选位置

```text
修改截图框选的区域，对照当前网站找到对应组件。
优化这里的图片、标题层级和留白，其他区域保持现有风格。
```

截图可以用于定位，也可以用于表达目标。两张截图用途不同，最好说“第一张是当前页面，第二张是参考效果”。AI 会对照源码定位，不照截图坐标写死布局。

### 参考网站或域名

```text
修改产品介绍区，图片氛围参考我发的网站链接。
先实际查看相关页面，再提炼适合当前网站的配色、光线和构图。
保留我们自己的产品、品牌和真实资料，不复制对方文案。
```

AI 实际查看可访问页面；只有域名也可以从首页开始。无法访问或无法看图时会说明，必要时请你补截图，不凭域名猜风格。网站页面地址不能直接传给生图接口当参考图片。

### 混合参考

```text
修改首页首屏：布局参考截图A，图片氛围参考网站B，
颜色沿用当前项目，产品使用我提供的原图。
同步优化标题和按钮文案，按钮仍链接到原来的产品分类页。
```

### 只改代码，不再生成

```text
只调整刚才 Banner 的标题位置、字号和手机端裁切，不重新生图。
```

### 只替换一张图

```text
只替换关于我们页面的场景图片，保留文字和布局。
最多生成1张，按当前页面容器规划比例并接入项目。
```

## 4. AI 会怎么使用生图工具

这是能力说明，不是要求你逐步确认的操作表：

1. 正常理解需求、读取项目和参考素材，确定实际需要的视觉内容。
2. 若需生图，结合页面容器、主体位置、文字留白和手机端裁切规划图片；纯色、渐变或简单装饰通常直接用代码实现。
3. 真实产品先查看原图；场景图先分析用途、物理关系、人物/道具必要性，避免关键词堆砌和不合理组合。
4. 检查连接、余额、数量与授权范围，调用 Cocoon，保存任务ID并查询结果。
5. 检查生成图，保存到项目资源目录，修改组件引用和相关文案、样式。
6. 正常检查代码、实际页面和移动端效果，报告完成情况及未验证部分。

不会因为用了这个 skill 就强制重构项目、换框架、整站重新设计或生成固定张数。你要求什么范围，就围绕该范围工作。

## 5. 首次配置 Cocoon MCP

已有有效连接直接复用；只有真正需要生图时才检查配置。

### 获取 Key

访问 [Cocoon 官网](https://mcp.boomclaws.com/) 注册、登录，在管理页获取 API Key。账号和充值由你操作。Key 只填在本机私密配置，不发到聊天、不放产品资料、不提交源码。

### 客户端 MCP 配置

在客户端 MCP 设置中添加：

| 配置项 | 内容 |
| --- | --- |
| 名称 | cocoon-ai，可自行命名 |
| 传输 | Streamable HTTP |
| 地址 | https://mcp.boomclaws.com/mcp |
| 请求头 | Authorization |
| 请求头值 | Bearer 后加一个空格，再填你的实际 Key |

支持 JSON 配置的客户端可参考 [配置模板](assets/mcp-config.example.json)。在本机私密配置替换占位值，不要直接覆盖整个现有配置。客户端界面与配置格式以其实际支持为准。

配置完成后可以说：“Cocoon MCP 已配置，请验证连接并查询余额。”必要时按客户端要求重新连接或重启。AI 使用实际发现的工具，不凭静态文档假定已连上。

### 本地参考图上传配置

MCP 生图需要可用的参考图片 URL，本地路径不能直接传入。随附脚本将本地参考图上传到该服务，得到参考 URL。

脚本从环境变量 `COCOON_IMAGE_KEY` 读取同一个 Cocoon Key。**MCP 请求头不会自动变成脚本环境变量**，因此连接能查余额但上传提示缺 Key 时，只需补上传配置。

Windows 可以在“编辑账户的环境变量”中新增用户变量：

```text
变量名：COCOON_IMAGE_KEY
变量值：你的实际CocoonKey
```

保存后重启执行脚本的客户端或终端，使新进程读到变量。不必在聊天里发送 Key，也不要打印变量值检查。

上传脚本使用 Python 标准库；可使用可用的 Python 3 解释器，建议3.12或以上。AI 可代为运行，普通用户无需手动执行：

```powershell
# 在 skill 目录执行；路径有空格时保留引号
python -X utf8 scripts/upload_reference.py --file "D:\素材\产品原图.png" --output "D:\本地任务数据\参考记录.json"
```

实际使用可用 Python 解释器和脚本的绝对路径；输出记录放在本地私密或忽略目录。脚本支持 PNG、JPEG、GIF、WebP、AVIF，单文件不超过20 MiB；它的类型识别不能代替图片内容检查。不支持的格式先准备适合上传的副本，保留原图。

已有可用的公网图片 URL 时可以直接引用，不必重复上传。用户要求使用该服务处理素材时，素材会提供给该服务；不要把私密资料当普通风格参考上传。

## 6. 费用怎么控制

生图前会显示实际查询余额、拟生成数量、规格和可核实费用。单价未知会明确说明，不猜“还能生成多少张”，也不承诺免费。数量不是固定套餐，由 AI 按页面需要规划，你可以限制：

```text
本次最多生成2张，每张1K，不额外付费重做。
```

也可以指定积分上限；当前价格无法核实、不能判断是否满足上限时，需要先说明，不能假装能保证。

- 已授权的数量与费用范围内连续执行，不逐张索取“继续”。
- 用户只要求改代码，不等于允许无限生成或重做。
- 多个画幅如果需要分别生成，是额外任务，应包含在数量内。
- 不擅自升级规格、换模型、充值或额外付费重做。
- 余额不足、认证失败或整体服务故障时停止新提交，完成其他可执行工作。
- 同一任务的多次查询按同一个 taskId 记录，不重复累加费用。
- 费用以服务实际返回记录为准，缺失项标未知，余额差额不能替代任务账单。

## 7. 图片怎样接入网站

AI 会将实际结果保存到项目既有资源目录，例如项目使用的 `public/images`、`src/assets` 或正式资源存储；具体遵循项目惯例，不强制目录名。

然后修改组件和样式，使页面实际使用新资源。标题、按钮和主要文案通常用 HTML 呈现，方便响应式和修改。根据页面需要处理裁切、尺寸、加载方式及替代文本。生产页面不依赖可能过期的生成结果 URL。

生成图先对照原图和用途检查，再到页面中看效果。图片单看好看，但手机端裁断产品、遮挡文字或与文案不符，都需要处理。产品失真、穿模、不合理操作或错误文字不能算合格。

未授权额外重做时，AI 会说明问题，并使用可信的原图/替代方案继续可执行部分，不把已知错误图当正式成品，也不把回退方案说成新图已交付。无法查看或运行项目时，会明确哪些检查没有完成。

## 8. 继续、调整和中断恢复

同一请求里的方向和授权持续有效，无需每改一个组件都确认一遍；新要求直接告诉 AI，由其判断影响范围。

```text
其他部分保留，只把刚才的场景改为更简洁的室内环境。
先说明这是否需要新生成和费用，不要自动重做。
```

中断后继续：

```text
继续上次修改。先查看已有代码和生图任务记录：
有任务ID就查原任务，有结果就保存，不重复生成已有图片。
```

只保留恢复所需的提示词、任务ID、素材与结果及费用记录，不强制复杂档案。换新聊天时建议说明项目位置和原任务记录位置；没有历史上下文的 AI 不能凭空知道上次进度。

提交超时却没有任务ID时，结果可能未知，先核验服务任务历史，不盲目重提。关闭聊天不等于取消已提交任务或自动退款。

## 9. 常见问题

| 情况 | 处理方式 |
| --- | --- |
| 找不到 skill | 让 AI 读取本目录 SKILL.md，或按客户端要求安装完整目录 |
| 没有生图需求却被要求填 Key | 不需要；直接要求按正常代码修改继续 |
| MCP 未连接或认证失败 | 检查 /mcp 地址、传输及 Bearer 头，私密更新 Key 后重连 |
| 能查询余额，但无法上传 | 检查脚本进程的 COCOON_IMAGE_KEY，设置后重启该客户端/终端 |
| 上传返回403或其他HTTP错误 | 保留状态和请求跟踪号排查，不能仅凭403断言是Key或Cloudflare问题 |
| 提示图片太大/格式不支持 | 准备支持格式且不超过20 MiB的副本 |
| 参考网站无法打开 | 提供截图、具体可访问页面或其他参考，不凭域名猜风格 |
| 生成很久没完成 | 保留taskId继续查询，AI可先做其他独立开发工作，不重新提交 |
| 已有结果但没保存 | 使用原结果恢复保存，不重新生图 |
| 产品外形或场景关系错误 | 明确指出问题；在授权内调整，否则保留待处理，不冒充合格 |
| 页面中图没显示/裁切不对 | 检查实际路径、加载和响应式布局，不默认重生图片 |
| 无法启动或没有浏览器检查能力 | 继续可执行工作，交付时说明未验证范围 |

## 10. 如何判断完成

交付应说明修改了哪里、文案/布局/交互变化、图片资源路径及代码引用，实际做过哪些检查，以及剩余问题。有生图时再补充实际可核实费用与余额；没生图不需要生图报告。

图片已生成、图片已保存、页面已接入、视觉和功能已验证是不同事实，不能互相替代。部署、提交或推送仍按你的实际指令和项目要求，不因为使用本 skill 自动执行。

详细工具约定见 [Cocoon 工具说明](references/cocoon-mcp.md)。上传工具已有离线测试；尚未在你的具体网站与真实付费账户上完成全流程联调，首次实际使用需核对连接、生成结果和页面效果。
