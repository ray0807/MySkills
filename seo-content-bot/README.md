# seo-content-bot · 每日 SEO 内容运营

让 AI 围绕你的业务研究近期关键词、新闻和读者问题，写出有具体场景、实用判断、来源和配图的文章，再通过你提供的 HTTP MCP 接口发布到指定网站。

这是可安装的 AI Skill，负责定义工作流程。**安装后不会自动每天运行**；需要配置品牌信息、联网与图片工具、发布接口，再启用宿主的每日定时任务。

## 一次运行会做什么

1. 读取品牌、产品及已发布文章，避免重复主题。
2. 搜索近期资料，核验新闻日期、技术事实及原始来源。
3. 选择与业务相关且能帮助读者的关键词和问题。
4. 写正文、标题、摘要、SEO 元信息、内链和行动建议。
5. 制作实际封面与必要正文配图，核对内容和素材权限。
6. 检查成稿，上传媒体，通过 MCP 发布并确认结果。
7. 保存文章包、研究证据和发布日志，供复盘和重试对账。

没有关键词数据工具时，会报告“观察到的词与搜索意图”，不会编造搜索量或难度。没有相关新闻时可以写常青内容；证据不足时允许跳过，不强行日更。搜索排名、流量和成交不保证。

## 快速开始

把整个 `seo-content-bot` 文件夹放入 AI 客户端的技能目录，或让支持本地文件的 AI 读取 [SKILL.md](SKILL.md)。安装方法见[技能库首页](../README.md#如何使用)。

**先配置发布接口，再制作文章。** MCP 和普通 HTTP API 均可。未提供接口时，AI 提示补齐地址、认证方式和目标站点/栏目；HTTP API 还需请求方法与字段说明。配置未完成或验证失败时暂停，不先写稿或配图。已有配置直接读取并检查。

配置接口：

```text
请使用 seo-content-bot，先帮我配置发布接口。
接口类型是【MCP / HTTP】，地址是【地址】，认证方式是【方式/无需认证】。
认证信息通过【环境变量/连接器】提供，目标是【站点/栏目】。
接口文档在【网址/文件】，HTTP 请求方法与字段以文档为准。
请做无副作用的连接和能力检查，不创建测试文章。
```

配置验证通过后，做一篇完整草稿：

```text
请使用 seo-content-bot。
我的网站是【网址】，业务是【产品/服务】，目标读者是【人群】，
目标市场是【国家/地区】，文章用【语言】。
先研究近期选题，写一篇有观点、有来源、带实际配图的文章。
使用草稿模式，数据保存到【绝对目录】。
我们已有的品牌和产品资料在【路径/网址】。
```

接入发布：

```text
这是我的 MCP 地址【地址】，认证信息通过【环境变量/连接器】提供。
请先发现工具和字段，确认媒体上传及发布状态查询能力。
我授权在【站点/栏目】自动发布【主题范围】内通过质量检查的文章，
每天最多 1 篇。不要重复发文，状态不确定时先查询对账。
```

启用每日运行时，再明确时间和时区，例如“每天北京时间 09:00 运行；失败或需要我处理时通知我”。定时任务需要可运行的宿主；关机、离线或工具不可用可能影响执行。

## 需要准备什么

| 项目 | 说明 |
| --- | --- |
| 业务资料 | 网站、产品、目标读者、市场、文章语言和真实品牌能力 |
| 搜索/浏览工具 | 获取最新资料并打开来源，单靠模型记忆无法核验近期信息 |
| 图片能力 | 用户素材、授权图库、图片生成或原创图表工具；必需图片缺失时保留草稿 |
| MCP 或 HTTP 发布接口 | 必需前置配置；提供地址、认证方式与目标，HTTP 需请求方法和字段说明 |
| 定时运行环境 | 宿主自动化或调度器，需具备搜索、图片、文件和 MCP 能力 |
| 分析数据（可选） | Search Console、关键词工具或站点分析，用于真实流量和转化复盘 |

不需要特定的 X、关键词或图库连接器。可用能力由运行环境决定。此版本没有针对未知 MCP 编写固定发布脚本，防止猜错接口；提供接口后按其能力接入。

## 配置与发布模式

复制 [assets/config.example.json](assets/config.example.json) 到独立数据目录并保存为 `config.json`，或者让 AI 根据你的回答生成配置。默认字段留空，不能视为已有业务事实或发布授权。

| 配置块 | 内容 |
| --- | --- |
| `brand` | 品牌、网站、产品、受众、地区、语言、语气和 CTA |
| `editorial` | 主题边界、研究预算、候选数量、新闻窗口和内链 |
| `images` | 封面要求、正文图数量、品牌素材位置和风格 |
| `publishing` | 模式、接口类型、MCP/HTTP 地址、请求方法、文档、认证方式、站点/栏目与能力映射 |
| `schedule` | 是否启用、用户时区、运行时间和成功通知偏好 |
| `analytics` | 可选分析接口及连接引用 |
| `data_dir` | 本地数据目录，推荐绝对路径 |

发布模式：

- `draft`：只保存本地完整文章包。
- `review`：给你查看文章和图片，获得发布授权后再发送。
- `auto`：在你明确授权的站点、栏目、主题和频率内自动发布，通过质量门槛后不逐篇重复询问。

三种模式都要求先配置并验证发布接口。默认是 `draft`。配置写 `auto` 本身不替代用户授权。你明确提出每日自动发布并指定范围后，可以持续执行；新增站点或超出范围需重新确定。

## 文章为什么能“有血有肉”

文章用具体问题、场景、取舍和可操作建议展开，避免泛泛的行业套话。真实产品经验和客户案例来自你的资料；缺少案例时用明确标注的假设场景，不能伪造“亲测”“采访”或客户评价。新闻提供背景，分析提出观点，两者分开写。

封面与正文图承担实际信息。生成示意图不冒充新闻照片或真实工厂；技术图和数据图使用可靠资料。成稿包含图片文件、alt 和用途说明，发布前上传为网站可引用的媒体。

## 发布如何防止重复和假成功

- 发现 MCP 工具与 schema，不猜接口和参数。
- 发布前记录稳定内容键；服务支持幂等时复用同一键。
- 请求超时先查询是否已经发出，无法确认就停止重发。
- 检查实际文章 ID 和发布状态；返回草稿不算正式发布。
- 尽可能查询或打开线上页面，核对正文和图片显示。

详细接入规则见 [references/publishing.md](references/publishing.md)。远程携带认证信息优先使用 HTTPS；明文 HTTP 需核对是否为可信本机/内网。

## 输出文件

每篇文章独立目录保存 `article.md`、`article.json`、`research.json`、`quality.json`、`media.json` 与 `images/`。数据目录另有运行和发布日志。

实际客户/品牌资料、文章草稿、日志与密钥配置放在数据目录，不提交到 Skill 源码仓库。接口凭据只通过环境变量或连接器使用。
